# S0 离线规格与变更规划

S0 交付的是可构建、可测试的离线基础：规格模型、严格输入校验、变更规划与操作保护。离线 CLI 不安装 CRD、不访问 Kubernetes 或 Curvine，不执行部署和运维操作。另一个二进制 manager 的进展见 [S1 控制面](s1-control-plane.md) 与 [S2 工作负载](s2-workloads.md)。

## 本地验收

使用 `go.mod` 指定的 Go 工具链，在仓库根目录执行：

```sh
make check build
bin/curvine-operator validate --file examples/cluster-development.json
bin/curvine-operator plan --file examples/cluster-production.json
bin/curvine-operator plan --file examples/cluster-scale-out.json --previous examples/cluster-production.json
bin/curvine-operator plan --file examples/cluster-scale-in.json --previous examples/cluster-production.json
```

最后一条命令应输出 `WorkerDrainRequired`、空 `steps` 并返回 **3**，这是预期的阻断结果。扩容示例从 3 个 Worker 增至 4 个，缩容示例从 3 个减至 2 个。示例中的镜像和 StorageClass 均为占位值，不能用于实际部署。

`make check` 包含单元测试、race、实际二进制验收、vet 和格式检查。二进制验收在临时目录编译并执行 CLI，直接检查进程退出码，不以 `go run` 的退出码代替。CI 已调用同一个检查入口；当前记录只代表本地执行结果。

## 输入契约

只接受一个 UTF-8 JSON 对象，最大 1 MiB（含空白）。字段名区分大小写；拒绝未知字段、重复字段（包括 Unicode 转义后相同的键）、任意位置的 `null`、额外文档、错误类型与非整数副本数。输入不支持 YAML，也不做隐式默认值填充。

| 字段 | S0 约束 |
| --- | --- |
| `apiVersion` / `kind` | `storage.curvine.io/v1alpha1` / `CurvineCluster` |
| `metadata.name` | 小写字母起始的 DNS label，最多 30 字符 |
| `metadata.namespace` / `spec.clusterID` | 小写字母起始的 DNS label，最多 63 字符 |
| `spec.clusterDomain` | DNS subdomain；生成的 Master FQDN 不超过 253 字符 |
| `spec.profile` | `development` 或 `production`；不表示已通过生产验收 |
| `spec.image` | 小写 repository + `@sha256:` + 64 位小写十六进制 digest；允许 DNS registry 和 1–65535 端口；S0 不接受 tag 或 IPv6 registry literal |
| `spec.deletionPolicy` | 仅 `Retain`；这是期望策略，S0 不执行任何资源删除 |
| `spec.master.replicas` | 1、3 或 5；production 仅允许 3 或 5 |
| `storage.storageClassName` / `storage.sizeGiB` | 显式 DNS subdomain 名称和正整数容量；不验证存储类是否存在 |
| `spec.workerPools` | 1–64 项；name 唯一、小写字母起始、最多 16 字符；replicas 在 1–10000；每池显式填写 storage |

上述规则由离线模型及解码入口实现。S1 已另外提供 CRD；其默认值、CEL 和 Go 校验分工见 S1 文档。镜像语法校验不证明镜像存在、支持目标 Curvine 功能或可被集群拉取。

## 命令与退出码

| 命令 | 行为 |
| --- | --- |
| `validate --file FILE` | 校验后向 stdout 输出 `{"valid":true,"scope":"offline-spec-only"}` |
| `plan --file FILE` | 输出首次创建的建议计划 |
| `plan --file FILE --previous OLD` | 比较两份期望规格；OLD 不是实际运行状态 |
| `help` / `--help` / `-h` | 输出帮助并返回 0；子命令也支持 `--help` / `-h` |
| `version` | 输出原型版本和 S0-offline 阶段 |

退出码 **0** 表示规格有效或计划没有静态阻断；**2** 表示输入/文件/输出错误，诊断写入 stderr；**3** 表示规格变更被阻断，完整计划仍输出到 stdout。参数解析可能附带帮助信息；无效规格不会输出部分计划。输出写入失败可能已经产生部分字节，调用方必须检查退出码。

## 计划契约

- `executable` 始终为 `false`。没有 apply、delete 或其他集群写入命令。
- `mode` 为 `bootstrap` 或 `update`；`cluster` 与 `clusterID` 标识目标身份。
- `desiredSpecHash` 对规范化后的整份规格（包含 API 类型和 metadata）计算 SHA-256。update 同时包含 `previousSpecHash`，用于追溯比较基线。Worker 池按名称排序，输入字段排列和池顺序不影响哈希。
- `steps[].replicas.from/to` 描述旧/新期望副本数；首次创建和新增池的 from 为 0。它们不是集群实际副本数。
- 首次创建步骤按身份检查、配置/服务、Master、仲裁检查、Worker 的顺序表达依赖。这些只是待实现流程的建议步骤，不代表检查已执行。
- 新增 Worker 池和扩容可输出建议步骤；相同规格返回空步骤。空步骤不代表线上资源已收敛。
- `runtimeChecksRequired` 列出执行任何未来操作前仍需完成的在线检查。必须重新读取 UID、generation、资源所有权、保留卷与应用健康，再重新规划。

| 阻断原因 | 触发条件 |
| --- | --- |
| `IdentityImmutable` | name、namespace、clusterID 或 clusterDomain 改变 |
| `ProfileMigrationRequired` | development/production 档位变化 |
| `RaftMembershipChangeRequired` | Master 副本数变化 |
| `WorkerDrainRequired` | Worker 池移除或副本数减少 |
| `StorageWorkflowRequired` | Master/Worker 存储类或容量变化，包含扩容 |
| `UpgradeWorkflowRequired` | 镜像引用变化 |

同一个请求只要命中任意阻断规则，整个计划的 steps 都为空；不会先输出其中的扩容步骤。格式不合法的新旧规格先返回输入错误，不作为有效阻断计划处理。

## 完成边界

S0 验收证明离线规则和 CLI 契约成立。它不证明调度、磁盘持久化、仲裁、数据可用性、安全 drain、升级、备份恢复或性能表现。后续工作按 [实施路线](roadmap.md) 推进。
