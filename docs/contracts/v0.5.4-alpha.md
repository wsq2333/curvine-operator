# Curvine v0.5.4-alpha 应用契约

> 本文原有 Worker 门槛描述针对普通集群。新增不可变读缓存用途的分配门槛、Mount Job、FUSE 和探针语义见 [读缓存契约](../read-cache.md)；quorum/全量数据可用性限制并未解除。

版本选择固定为 [v0.5.4-alpha](https://github.com/CurvineIO/curvine/releases/tag/v0.5.4-alpha)，源码 commit `89df141912e96d127421de6e4d36e6e2190d9949`。本次直接核查固定源码；没有修改 Curvine 仓库。契约名为 `curvine-v0.5.4-alpha`。它表示适配依据，不代表实际镜像或运行中的 Master 已验证为此版本。

## 与 S1/S2 的关系

- S1 的 `Observer` 抽象保持只读，新增 `internal/curvine/v054` 实现。Controller 继续执行 UID/generation、超时、样本时效和 status 乐观锁检查。
- S2 的构建器复用既有资源布局，增加明确的发布契约标记。保留旧 `curvine-728d2a46` 契约；已有不同契约的资源报 `RuntimeContractConflict`，不会自动迁移。
- 无参数时仍是观察模式和 Unsupported Observer。`--observer-contract=curvine-v0.5.4-alpha` 仅启用真实 HTTP 观察；`--workload-contract=curvine-v0.5.4-alpha` 同时启用资源管理和该 Observer。不同版本的 Observer/运行契约组合会在启动时拒绝。
- `config/workloads` 显式选择新契约。旧部署不能直接更换契约参数后当作完成版本升级。
- 不增加 Kubernetes 权限、Pod exec、Secret 读取或上游写接口；S0 离线规划不受影响。没有增加模拟健康或绕过 quorum 的开关。

## HTTP 与观测语义

来源：[Master router](https://github.com/CurvineIO/curvine/blob/89df141912e96d127421de6e4d36e6e2190d9949/curvine-master/src/master/router_handler.rs)、[Master monitor](https://github.com/CurvineIO/curvine/blob/89df141912e96d127421de6e4d36e6e2190d9949/curvine-master/src/master/master_monitor.rs)、[WorkerInfo](https://github.com/CurvineIO/curvine/blob/89df141912e96d127421de6e4d36e6e2190d9949/crates/common/curvine-model/src/worker_info.rs)、[Worker map](https://github.com/CurvineIO/curvine/blob/89df141912e96d127421de6e4d36e6e2190d9949/curvine-master/src/master/fs/state/worker_map.rs)、[ComponentInfoProto](https://github.com/CurvineIO/curvine/blob/89df141912e96d127421de6e4d36e6e2190d9949/crates/common/curvine-proto/proto/common.proto)。

| 能力 | 接口/证据 | 当前处理 |
| --- | --- | --- |
| Master 角色与身份 | 各 Master Pod 的 `GET /api/overview`：cluster_id、master_addr、master_state | 校验预期 clusterID 和完整 Master RPC 地址，记录 Active/Standby/SafeMode/Exit |
| Worker 注册 | 唯一 Active Master 的 `GET /api/workers` | 校验 live/lost 列表、Worker ID/地址/会话、状态、所属池、心跳和存储；按池报告实际注册数 |
| Worker 构建来源 | Worker 的 component_info | 校验 Git commit、可选 tag、protocol/min_protocol 均为 1；不把 software_version 当发布标签 |
| Master 运行版本 | 此 HTTP 契约无对应证据 | `MasterVersion.supported=false`；不填 `observation.version` |
| Raft quorum | Active 仅表示本节点报告 Leader，没有当前多数派响应/租约证明 | `QuorumHealthy=Unknown`，reason `NoQuorumProofEndpoint` |
| 数据可用性 | overview 的容量和文件计数不是实际读写/副本可用性证明 | `DataAvailable=Unknown`，reason `NoDataReadProofEndpoint` |

在所有预期 Master 可达且恰有一个 Active 时读取 Worker inventory，并再次读取所有 Master 角色。可见的切主、多个 Active 或部分 Master 不可达时不发布 Worker 计数，保留 Unknown。两轮角色检查并非原子采样，不能证明不存在 ABA 切主或网络分区，因此始终不推断 quorum。

`/api/workers` 的 `live_workers` 数组来自 Master 当前 Worker map，其中可能包含 Decommission/Blacklist，不能直接以数组长度作为健康 Worker 数。Registered 只计匹配预期池、ordinal 和 RPC 端口且状态为 Live 的记录；Fresh 另外要求 Master 记录的心跳不超过 30 秒，容忍最多 5 秒时钟领先；VersionVerified 另外校验结构化构建来源。30 秒是本适配器的保守新鲜度阈值，不是上游 lost-worker 超时。三项计数独立，Desired 仅是对照值。

`WorkersHealthy=True` 表示所有期望 Worker 均满足注册、心跳、构建、会话和存储报告要求，**不证明实际 I/O 可用**。缺少 component_info/会话时不能判健康；已知不匹配、缺失注册、失联/黑名单/排空、空存储或失败磁盘判 Unhealthy。格式或身份不合法则拒绝整个样本。没有读取 inventory 时计数缺省，成功读取空列表时计数为 0。

源码 Cargo workspace 版本为 `0.2.2`，构建环境可覆盖 BUILD_VERSION。故使用完整或至少 7 位的匹配 Git commit，且已提供的 tag 必须为发布标签（空/unknown 视为未提供）；协议范围严格为 1。Worker 构建信息来自 Master 保存的报告，没有证明镜像 digest、Master 构建或供应链签名。

HTTP 请求仅访问根据 CR 推导的 Master Pod FQDN 的 9000 端口，禁用环境代理和重定向，不跟随响应中的地址。仅允许两个上述只读路径，不访问可能暴露配置的 `/api/config`，也不调用名称为 GET 的排空等变更接口。强制 JSON Content-Type、4 MiB 响应上限、有效 UTF-8、无重复键/尾随文档；要求必要字段存在且类型正确，兼容新增字段。端点未知路由可能返回 WebUI HTML 和 200，不能当作正常响应。HTTP 单请求最长 3 秒，连接/响应头最长 2 秒，并服从 Controller 默认 5 秒总观察时限。

该契约使用集群内明文 HTTP；身份字段用于一致性核对，不是服务器认证。网络/DNS 与 Master 数据须处于可信管理边界；若部署要求 TLS/认证，应新增明确的传输契约，而不是跳过验证。状态不包含原始响应、URL、配置或远端错误。

## 启动与配置契约

核查依据：[服务入口](https://github.com/CurvineIO/curvine/blob/89df141912e96d127421de6e4d36e6e2190d9949/curvine-server/src/bin/curvine-server.rs) 和固定源码内的 ClusterConf、Master/Journal/Worker 配置及 journal 初始化实现。

- 继续使用 `/app/curvine/lib/curvine-server --service master|worker --conf /etc/curvine/curvine-cluster.toml`。
- `CURVINE_MASTER_HOSTNAME` 覆盖 Master/journal 的完整 Pod DNS，Worker 使用 `CURVINE_WORKER_HOSTNAME`。
- 显式配置 Master RPC/Raft/Web 为 8995/8996/9000，Worker RPC/Web 为 8997/9000。Observer 与生成的 headless service/Pod 地址一致。
- `format_master=false`、`format_worker=false`；保留现有元数据、journal、Worker PVC 路径和 Retain/OnDelete 语义。空目录初始化与已有目录恢复不依赖主动 format。
- `--version-json` 是二进制本地命令，不是远程 HTTP 版本接口；本次没有引入 exec 权限执行它。

这些是源码级适配，未取得经过实机验证的 release 镜像 digest。镜像仍须满足现有非 root/只读根目录、路径、依赖库及 PVC 权限要求。不能将测试样例镜像当作发布物。

## 状态、门控与剩余工作

新增 `status.observation.application`：contract/sourceCommit、reason、capabilities、masters，以及每池 desired/registered/fresh/versionVerified。数量受 CRD 限制，不把全量 Worker 列表写入 status。原 `version` 改为可选；旧 Observer 返回实际版本的方式仍兼容。失败/过期/UID 或 generation 不匹配时清除整个当前 observation。

ObservationReady=True 只表示成功取得并校验了样本，不代表能力完整或应用健康。资源引擎仍可创建 Master 和支持资源；到 Worker StatefulSet 变更时，缺少 quorum 证明会报 `ResourcesReady=False/QuorumObservationUnsupported`，Progressing=False，保留定时重新观察，不伪装成持续推进中的操作。

这意味着本次补齐了发布版可用的 S1/S2 应用接入与契约测试，但**没有完成 S1/S2 所有上线验收条件**。下一步需要上游提供或单独实现可验证的 quorum/数据可用性与 Master 版本来源，然后选定真实镜像和存储环境完成创建、读写、重启、卷保留/恢复测试。S3/S4 的指标、Operation、drain、升级等未在本次实现。

本次测试命令、通过结果与边界见 [验证记录](../validation-v054.md)。
